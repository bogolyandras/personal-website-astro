# AGENTS.md

Guidance for AI coding agents working in this repository.

## Commands

```bash
bun install       # install dependencies
bun run dev       # start dev server (http://localhost:4321)
bun run build     # production build to dist/
bun run preview   # preview the production build locally
```

There are no tests or linting scripts configured.

## Development

When starting the dev server, use background mode:

```
bunx astro dev --background
```

Manage the background server with `bunx astro dev stop`, `bunx astro dev status`, and `bunx astro dev logs`.

## Stack

- **Astro 7** — file-based routing under `src/pages/`; `.astro` files use a frontmatter fence (`---`) for server-side JS/TS and HTML below it
- **TypeScript** — strict mode via `astro/tsconfigs/strict`; all `.ts`/`.astro` files are included
- **Bun** — package manager (`bun.lock`); CI (`.github/workflows/node.js.yml`) installs with `bun install --frozen-lockfile` and builds with `bun run build`

## Project state

The project was re-scaffolded from the Astro `minimal` template with Bun.
Pages:
`src/pages/index.astro` (home),
`src/pages/contact.astro`
`src/pages/404.astro`,
all wrapped in `src/layouts/BaseLayout.astro`
(takes a `pageTitle` prop) and styled by `src/styles/global.css`.

Name, title and profile links live in `src/data/profile.ts`; the pages and `/llms.txt`
(generated by `src/pages/llms.txt.ts`, see https://llmstxt.org) both read from it, so edit links there.
`public/favicon.svg` is the only icon source: the `astro-favicons` integration renders `/favicon.ico` and
`/apple-touch-icon.png` from it at build time and injects the icon `<link>` tags, so don't add them to the layout by hand.
`site` in `astro.config.mjs` is set to `https://www.bogolyandras.com`.

Integrations: `@astrojs/sitemap` (generates `sitemap-index.xml`, referenced from `public/robots.txt`) and
`astro-favicons` (configured in `astro.config.mjs` to emit only the favicon set and one apple-touch-icon).
When adding integrations (e.g. Tailwind, MDX, React), use `bunx astro add <name>` or register them
in `astro.config.mjs` via `defineConfig({ integrations: [...] })`.
